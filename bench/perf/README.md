# Side-by-side CPU perf: viva_tensor vs NumPy

Honest baseline for pure-Gleam `viva_tensor` against NumPy on the same CPU,
same shapes, same ops. The goal is **not** to win — it is to measure where the
pure-Gleam path stands today so future NIF/Zig integrations have a concrete
delta to point at.

> Realistic expectation: viva_tensor is **10x–1000x** slower than NumPy on
> CPU-bound ops without the NIF. That gap is exactly what the native backends
> exist to close.

## Files

| File                      | What it does                                                      |
|:--------------------------|:------------------------------------------------------------------|
| `compare_numpy.py`        | Times NumPy for each op/size, writes `numpy_results.csv`.         |
| `compare.py`              | Reads both CSVs and prints a side-by-side table.                  |
| `numpy_results.csv`       | NumPy median per-op timings (generated).                          |
| `viva_tensor_results.csv` | viva_tensor median per-op timings (generated by the Gleam bench). |

The Gleam half lives at `dev/viva_tensor/bench/perf.gleam` and runs as
`viva_tensor/bench/perf`.

## Run

```bash
python bench/perf/compare_numpy.py
gleam run -m viva_tensor/bench/perf
python bench/perf/compare.py
```

The Python step needs only stock NumPy — no torch, no scipy.

## Ops & shapes

| Op           | Shape(s)                                                 |
|:-------------|:---------------------------------------------------------|
| `matmul`     | `(1024,1024) @ (1024,1024)`, `(2048,2048) @ (2048,2048)` |
| `transpose`  | `(2048,2048)`                                            |
| `add`        | `(1024,1024)`, `(2048,2048)` (element-wise)              |
| `mul`        | `(1024,1024)`, `(2048,2048)` (element-wise)              |
| `sum`        | full reduction over `(2048,2048)`                        |
| `softmax`    | `(512,1024)` per-row                                     |
| `layer_norm` | `(512,1024)` along last axis                             |

## Iteration policy

* **NumPy** — 5 warmup + 20 timed iterations per op. Median reported.
* **viva_tensor** — 5 warmup + 20 timed for cheap ops; **1 warmup + 3 timed**
  for the heavy paths (`matmul 1024+`, `transpose 2048`, `add/mul 2048`) so
  one full bench run finishes in well under 5 minutes even on a slow box.
  Median reported.

Both halves use `time.perf_counter` / `erlang:monotonic_time` at the
outer-loop level. No statistical magic — just medians.

## CSV columns

```
op,size,iters,total_ms,per_op_us,gflops_estimate
```

`gflops_estimate` is a rough order-of-magnitude check, **not** a peer-reviewed
roofline. matmul uses `2*n^3` FLOPs; element-wise ops count `n*n` ops;
softmax/layer_norm assume ~5 ops/element.

## Notes

* viva_tensor's `matmul` here goes through the pure-Gleam path (`t.matmul`).
  Native backends (Apple Accelerate, Zig SIMD, CUDA) live behind `*_accelerated`
  variants and are out of scope for this baseline — they get their own bench.
* The bench harness is **not** part of the Hex package: `bench/perf/` lives
  outside `src/` and `dev/viva_tensor/bench/perf.gleam` is a development-only
  entry point.
