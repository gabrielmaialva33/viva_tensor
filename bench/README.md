# bench/

External benchmark and comparison tooling. Anything that runs **outside**
the Gleam package API lives here — Python and R scripts for statistical
analysis, cross-runtime comparisons against PyTorch / NumPy, shell
runners, results, and the technical plans behind the numbers.

Gleam-side benchmark entrypoints (the ones invoked via
`gleam run -m viva_tensor/bench/...`) live under
[`dev/viva_tensor/bench/`](../dev/viva_tensor/bench/) instead — kept out
of `src/` so they don't ship in the Hex package.

## Quick start

```bash
# Head-to-head vs PyTorch / NumPy (matches dev/viva_tensor/bench/showdown.gleam)
.bench-venv/bin/python3 bench/python/compare/numpy_pytorch.py
# -> writes bench/results/pytorch_results.term

# CPU-only NumPy baseline
python3 bench/python/compare/numpy_cpu.py
# -> writes bench/results/numpy_cpu_baseline.csv

# Side-by-side table (after running both halves)
python3 bench/python/compare/side_by_side.py

# Full statistical sweep with bootstrap CI
python3 bench/python/benchmark.py

# CUDA peak FLOPS / TOPS
python3 bench/python/gpu_benchmark.py

# Drive everything in one go (CI)
./bench/scripts/run_benchmarks.sh
```

## GPU benchmark procedure (READ THIS BEFORE RUNNING)

GPU matmul benchmarks on consumer NVIDIA cards (RTX 30/40/50 series) are
**invalid by default** because the driver power state stays in idle
(~1005 MHz on a 4090) when individual kernels finish in <20 ms. Without
intervention, you will see fake "anomalies" where the same shape reports
46 TFLOPS in one run and 256 TFLOPS in the next — the hardware is the
same, only the clock changed.

### Required setup

```bash
# 1. Persistence mode + lock GPU clocks to boost frequency
sudo nvidia-smi -pm 1
sudo nvidia-smi --lock-gpu-clocks=2520,2520    # RTX 4090 boost (Ada SM 8.9)
# For other cards: check nvidia-smi --query-supported-clocks=graphics --format=csv

# 2. Verify the lock took effect
nvidia-smi --query-gpu=clocks.gr,clocks.max.gr --format=csv,noheader
# Expected: "2520 MHz, 3105 MHz"

# 3. Run the benchmark
python3 bench/python/gpu_benchmark.py

# 4. Release the clock lock when done
sudo nvidia-smi --reset-gpu-clocks
```

### Why this is necessary

- viva_tensor's NIF path is **so efficient** (~2 µs Python→NIF→CUDA
  dispatch) that the GPU power manager sees almost no sustained load and
  refuses to boost. PyTorch's heavier Python overhead (~50 µs/call)
  accidentally keeps the GPU "warm" — making PyTorch look more stable in
  unlocked benchmarks, not because of better code.
- Without the lock, results for 4000²–6000² shapes are dominated by
  whether the boost kicked in mid-run, producing variance that has
  nothing to do with the matmul backend.

### Validation: 6000² FP16 viva_tensor

| State | Median TFLOPS | GPU clock |
|---|---:|---:|
| Default (idle policy) | 46 | 1005 MHz |
| `--lock-gpu-clocks=2520,2520` | **256** | 2520 MHz |

The hardware is identical. The "anomaly" was a measurement artifact.

### What to look for in the output

- `gpu_benchmark.py` calls `viva_tensor_zig:cuda_sync()` inside the
  timer loop, so the times reported are **kernel-only** (CPU launch is
  ~2 µs and dwarfed by the kernel).
- Per-shape coefficient of variation should be <5%. If you see CV >15%
  on a single shape, the clock is bouncing — re-check the lock.

### Multi-run aggregation

For mean/median/mode across multiple complete runs, use
`bench/python/run_5x.py N`:

```bash
sudo nvidia-smi --lock-gpu-clocks=2520,2520
python3 bench/python/run_5x.py 5    # 5 CPU runs + 5 GPU runs
sudo nvidia-smi --reset-gpu-clocks
```

Output lands in `bench/data/run_5x_<timestamp>.json` with raw samples
plus aggregated mean/median/mode per (library, dtype, size).

## What changed in this reorg

- `compare/` (RESULTS, plans, numpy_pytorch.py) and `perf/` (NumPy CPU
  scripts + CSV) were merged: scripts under `python/compare/`, outputs
  under `results/`, plans under `plans/`.
- `python/benchmark_compare.py` was redundant with
  `compare/numpy_pytorch.py` and was moved to `results/archive/` as
  legacy reference.
